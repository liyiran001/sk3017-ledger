# AI 协作记录

> 路线 B 必交材料。按课程要求记录关键提示词，格式：**意图 / 提示词 / AI回复摘要 / 我的修改与采纳**。
> 说明：本项目使用 DeepSeek Harness 作为 AI 编程助手，由我在每一步给出约束与验收标准，AI 生成代码后我逐段阅读、运行、改写。

## 第 1 条：把课设要求变成可执行的选题决策

**意图**：在 7 道题里选一个投入产出比最高、又不容易在评阅时"功能不完整"的题目。

**提示词**：
> 这是 SK3017 的课程设计要求和 7 道题的题库（附文件）。评分是功能完整性 40%、代码质量 20%、界面 15%、可视化 10%、报告 10%、过程 5%。我只有 15~20 小时。请对比 7 道题在"实现风险/验收难度/得分上限"三个维度上的差异，给出唯一推荐，并说明为什么不选另外几道。

**AI回复摘要**：逐题对照评分表分析，指出题目二（图片上传）、四（拖拽持久化）、七（真实 API Key + 额度）都有"演示时功能可能不可用"的风险，题目五没有界面会直接损失 15 分；推荐题目三，理由是功能边界清晰、图表要求与 10% 可视化分完全对齐、有预算提醒作为加分项。

**我的修改与采纳**：采纳题目三。但我没有照单全收"选完就写代码"，而是先要求 AI 把数据库设计单独产出一份文档给我审——因为我判断 ER 设计错了后面全要返工。

## 第 2 条：先定数据模型，再写任何一行业务代码

**意图**：避免"边写边改表"，也为了报告里的"数据库设计"章节有素材。

**提示词**：
> 按题目三写数据库设计：MySQL 8.0，需要支持金额、收支类型、分类（含系统预置 + 用户自定义）、日期、备注、月度预算。要求：1) 给出 ER 图和每张表的字段/类型/约束；2) 说明为什么金额用 DECIMAL 不用 FLOAT；3) 给出三张图表对应的聚合 SQL；4) 明确索引怎么设计、为什么。

**AI回复摘要**：给出 4 张表（users/categories/records/budgets）、复合索引 `(user_id, record_date)` 等三条、DECIMAL 与浮点的取舍、以及饼图/柱状图/折线图三条 SQL；特别提示"没有数据的月份 SQL 不会返回行，直接交给 ECharts 会导致 x 轴错位"。

**我的修改与采纳**：采纳整体结构，但我把 `categories` 的预置分类方案从"每个用户复制一份"改成了"user_id=0 存模板行 + 注册时复制"——因为前者在文档里被写成"预置行属于用户"，我读代码时觉得 `user_id` 为 0 的语义更清晰，也让首次登录复制逻辑可追溯。**这条"缺口处理"提示后来直接省掉了一个图表 bug。**

## 第 3 条：让 AI 按分层结构搭骨架，而不是堆一个 app.py

**意图**：要"代码质量 20%"的分，就不能把 800 行全塞进一个文件。

**提示词**：
> 用 Flask 应用工厂 + 蓝图重构：config（全部配置走环境变量，.env 加载）、extensions（db 单独放避免循环导入）、models、utils（登录装饰器、金额/日期解析）、blueprints/auth、main、records、stats。要求：不要在 import 时连数据库；敏感配置不能出现在代码里；模板用 Jinja2 继承 base.html。

**AI回复摘要**：给出 create_app 工厂、4 个蓝图、extensions 单例模式，并解释了"为什么 db 要单独一个文件"（循环导入）。

**我的修改与采纳**：采纳。我额外补了 `SQLALCHEMY_ENGINE_OPTIONS` 里的 `pool_pre_ping` 和 `pool_recycle`——AI 没提，但我知道 MySQL 闲置 8 小时会断连，演示时如果服务开了一晚上，第一个请求就会 500。

## 第 4 条：金额和日期的校验必须发生在服务端

**意图**：题目要求"金额字段校验：非负、保留两位小数；日期合法性校验"，我不想只靠前端 `type=number`。

**提示词**：
> 写服务端校验：金额要转 Decimal、拒绝负数和非数字、量化到两位小数；日期用 YYYY-MM-DD 解析、非法格式返回表单错误而不是 500。非法输入要 flash 回原表单并保留用户已填内容，不要抛异常。

**AI回复摘要**：给出 `parse_amount()` / `parse_date()`，用 `Decimal` + `quantize`，捕获 `InvalidOperation`/`ValueError` 后 `raise ValueError("中文提示")`，视图里统一 `except ValueError as exc: flash(str(exc))`。

**我的修改与采纳**：采纳，并追加了上限校验（超过 99999999.99 拒绝，避免 DECIMAL(10,2) 溢出报数据库错误）。还加了一条 AI 没想到的：**类型字段不信任前端传值，按 category_id 反查分类的 type 回填**，否则用户可以提交"收入类型 + 支出分类"的脏数据。

## 第 5 条：图表接口的聚合要留在 SQL 里

**意图**：题目明确"筛选与统计在服务端完成（SQL 聚合），不允许把全表拉到前端再算"，这是评分点。

**提示词**：
> 写四个统计接口：本月收支汇总、当月支出分类占比、近 6 个月收支对比、当月每日支出。要求：聚合全部在 SQL 完成（GROUP BY + SUM）；没有数据的月份/日期在 Python 层补 0，保证 x 轴连续；月份参数非法时返回 400 JSON 而不是 500。

**AI回复摘要**：给出四条 SQLAlchemy 查询，用 `func.year/func.month/func.day` 分组（避免 `DATE_FORMAT` 里的 `%` 和 pymysql 参数化冲突），并用 Python 生成连续坐标轴。

**我的修改与采纳**：采纳。这里我做了两个判断：一是**拒绝** AI 一开始想用的 `DATE_FORMAT(record_date, '%Y-%m')`，因为 `%` 在 pymysql 参数化时要做转义，容易踩坑，改用 `YEAR()/MONTH()`；二是把 `months` 参数夹到 3~12 之间，防止有人传 `months=9999` 拖垮查询。

## 第 6 条：让 AI 自己写测试来证明功能是通的

**意图**：不靠"我点了一遍看起来没问题"，要有可复现的证据。

**提示词**：
> 写一个端到端冒烟测试脚本（只用标准库 urllib，不要引入 requests）：覆盖未登录跳转、注册、登录、密码错误、新增、负数/非数字/非法日期、列表筛选、四个统计接口、预算保存、CSV BOM、404 越权、退出。每条断言打印 PASS/FAIL，最后统计通过数。注意断言状态码而不是页面文案。

**AI回复摘要**：给出 25 项断言的脚本，但第一版让 urllib 自动跟随 302，导致"注册成功"被判成 200 失败。

**我的修改与采纳**：我让 AI 加了 `NoRedirect` handler 禁用自动跳转，才能断言 302 本身。跑出 9 个 FAIL 后，我没有让 AI"改测试直到通过"，而是要求**先判断是测试错了还是代码错了**——结果查出两个真 bug（BUG-001 的 GROUP BY、BUG-002 的 401 语义）和一个测试自身的 bug（BUG-005 硬编码 category_id）。

## 第 7 条：把踩过的坑写成能复用的 Debug 日志

**意图**：课程要求 Debug 日志"下次遇到同样报错的人照着做就能脱困"。

**提示词**：
> 把今天这几条报错整理成 Debug 日志：现象（贴报错原文）→ 根因（为什么错，不要只说"少写了 GROUP BY"，要说清楚 MySQL 为什么要这个 GROUP BY）→ 解决（给代码）→ 预防（下次怎么在写的时候就避免）。末尾写一段复盘，把这些 bug 归类。

**AI回复摘要**：产出 5 条日志和"SQL 正确性 / Web 语义边界 / 测试工具本身也会错"三类复盘。

**我的修改与采纳**：采纳，但我要求把 BUG-004（curl 传中文导致表单解析为空）也写进去——虽然那不是应用 bug，但"排查时先打印服务端收到的值"这个教训是真的，删掉就少了一条经验。

## 我对自己使用 AI 的评价

- **AI 加速的部分**：样板代码（蓝图注册、模板结构、ECharts option）、SQL 草稿、文档初稿。这部分省了大概 40% 的时间。
- **AI 帮不上、必须我自己判断的部分**：数据模型是否符合"用户隔离"要求、错误提示该不该暴露账号是否存在、测试失败到底是代码错还是测试错、演示数据要造得多真实才经得起老师抽查。
- **我踩过的坑**：一开始太信任 AI 给的测试结果（第一次 9 个 FAIL 差点以为是代码全错），后来学会"先看是断言写错了还是实现错了"。这条写进了 BUG-005 的预防栏。
