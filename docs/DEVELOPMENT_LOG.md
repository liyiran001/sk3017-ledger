## 二、开发日志（按日期）

### 2026-10-28（周三）M0：环境、数据库、项目骨架 —— 🚩 M0

**今日进展**：确认本机原来只有 MySQL Workbench 客户端、没有 MySQL 服务端，于是下载 MySQL 8.0.43 的免安装 ZIP 包，解压后写 `my.ini`（端口 3306、utf8mb4、时区 +08:00），用 `--initialize-insecure` 初始化数据目录，设 root 密码，再用 `mysqld --install MySQL80` 注册成 Windows 服务，这样开机自启、不用每次手动起。随后按设计稿写 `database/schema.sql`：4 张表（users / categories / records / budgets）、外键、CHECK、3 个复合索引、13 条预置分类，执行通过。项目这边用 `python -m venv` 建虚拟环境，装 Flask 3.1.3 / Flask-SQLAlchemy 3.1.1 / PyMySQL 1.2.3 / python-dotenv，按 `create_app` 工厂 + 蓝图的分层把骨架搭起来（config / extensions / models / utils / 4 个蓝图）。

**遇到问题**：命令批量写代码时有一次把两个文件写在同一条命令里，第二个文件被截断成半行——不是代码问题，是"一次改太多、出错了不知道断在哪"，后来改成一次只写一个文件（见 DEBUG-003）。

**产出**：可运行的数据库 + 应用骨架 + 16 条路由（`/`、`/auth/*`、`/records/*`、`/stats/api/*`）。

**里程碑**：M0 ✅

### 2026-10-28（周三）M1：用户模块 —— 🚩 M1

**今日进展**：完成注册/登录/退出三个视图。注册时用正则校验用户名（3~20 位字母数字下划线中文）、密码长度 ≥6、两次一致、查重；关键是注册成功后把 `categories` 里 `user_id=0` 的 13 条预置分类复制一份给新用户——这样每个用户既有系统分类又能自己加，表格不会随着用户数膨胀。密码用 `werkzeug.security.generate_password_hash`（scrypt）存哈希，登录用 `check_password_hash` 校验；登录失败统一提示"用户名或密码错误"，不暴露账号是否存在。登录跳转做了 `_safe_next()`，只允许站内相对路径，防 open redirect。

**遇到问题**：`login_required` 第一版对所有 `/records`、`/stats` 路径都返回 401 JSON，结果浏览器直接访问 `/records/` 时看到的是一段 JSON 而不是登录页（见 DEBUG-002）。

**产出**：注册/登录/退出可用，未登录访问受保护页面会跳转到登录页并带 `next` 参数。

**里程碑**：M1 ✅

### 2026-10-28（周三）M2：记账核心 CRUD + 筛选 —— 🚩 M2

**今日进展**：`records` 蓝图完成列表（按月份 + 类型 + 分类组合筛选，每页 15 条）、新增、编辑、删除、CSV 导出。所有查询都带 `records.user_id == 当前 session 用户` 条件，取单条记录时再校验一次归属，改 URL 里的 id 也越不了权。金额统一走 `parse_amount()`：转 `Decimal`、校验非负、量化到两位小数，非法输入抛 `ValueError` 被视图接住、flash 回表单——所以负数和非数字金额都不会进库。类型字段不信任前端传值，而是按 `category_id` 反查分类的 `type` 回填。CSV 用 `io.StringIO` + `csv.writer` 生成，开头拼 `\ufeff` BOM 解决 Excel 中文乱码。

**遇到问题**：列表页顶部"本月收入/支出合计"的聚合 SQL 少写 `GROUP BY`，MySQL 8 默认 `only_full_group_by` 直接报 1140 错误，整页 500（见 DEBUG-001）。

**产出**：记账闭环可用；`scripts/smoke_test.py` 25 项断言全部通过。

**里程碑**：M2 ✅

### 2026-10-28（周三）M3 + M4：统计三图 + 预算提醒 —— 🚩 M3 / 🚩 M4

**今日进展**：统计接口四个：`/api/summary`（本月收支 + 预算使用率）、`/api/pie`（当月支出按分类，`GROUP BY categories.id` + `SUM`）、`/api/bar`（近 6 个月收支，`GROUP BY YEAR(), MONTH()`）、`/api/line`（当月每日支出，`GROUP BY DAY()`）。**所有聚合都在 SQL 里完成**，前端只渲染，符合题目"不允许把全表拉到前端再算"的要求。缺口处理放在 Python 层：柱状图用循环生成连续 6 个月坐标轴、结果按 `YYYY-MM` 塞槽位，没数据的月补 0；折线图用 `calendar.monthrange` 算当月天数、按 1..N 补齐，避免出现"2 月 31 日"这种笑话。前端 `static/js/stats.js` 用 ECharts 画三张图，月份选择器 change 时四个接口一起重拉，实现联动；ECharts 和 Bootstrap 都下载到 `static/vendor/` 本地，断网也能演示。预算用 `budgets` 表的 `(user_id, month)` 唯一键做幂等保存，支出达 80% 显示黄色提醒、达 100% 变红。

**遇到问题**：ECharts 的柱状图和折线图如果 x 轴数组和数值数组长度不一致，图不会报错但会整体错位——所以补零逻辑不是"优化"，是正确性要求（这条和课程 Debug 示例里的 BUG-003 是同一类问题，我在设计阶段就规避了）。

**产出**：三张图正常出图，且饼图/柱状图/折线图/概览卡的当月支出合计完全对齐（2677.01）。

另外补了 `database/seed.py`（demo 账号 + 近 3 个月 69 条记录 + 当月预算 3000 元），并用无头浏览器把首页、记账明细、统计页、记账表单各截了一张图放进 `screenshots/`。造数时踩了两个坑：月份偏移量写成正数、数据全生成到未来（DEBUG-006），以及对数时忘了加 `user_id` 条件（DEBUG-007）。

**里程碑**：M3 ✅　M4 ✅
